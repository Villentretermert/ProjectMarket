# PM-022 · Наблюдаемость и нагрузка

Состояние: in_progress. Задача не принята, полный L2/CI ещё выполняются.

Реализованы JSON-логи без payload/секретов, локальный CLI метрик/alerts, ротация,
per-bot history/source/request budgets, outbox admission/retention/floor, worker
cleanup, pools соединений и ускоренная проверка канонической Message schema.

[оперативная инструкция](../setup/OPERATIONS.md).

## Диагностика и повторная проверка

| Прогон | Что проверено | Результат |
|---|---|---|
| Без pooling | Только подготовка до90 браузеров | Остановлен из-за роста latency ещё до steady, не L2 |
| С pooling,120с | 100 ботов/100 клиентов,2 000 сообщений +burst3 000 | Все5 000 квитанций сохранились, но steady live p95=5.151с,140 промежуточных ревизий не отображены, SLO FAIL |
| Compiled Message schema,120с | 100 ботов/100 клиентов,2 000 сообщений | 2 000/2 000 отображены, live p95=1.988с,p99=2.144с; ingest HTTP p95=149мс,p99=345мс;0errors, restart counts PASS |

Первое замедление устранено повторным использованием соединений; второе связано
с CPU hot path проверки графиков. Сама схема не менялась. Дифференциальные тесты
проверяют эквивалентность примеров и граничных мутаций исходному валидатору.
Нагрузка запускалась на общем компьютере с другими активными приложениями.
Короткая успешная репетиция не заменяет30минут L2.
