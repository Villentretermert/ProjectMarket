# PM-009 · публикация и чтение каналов

22 октября 2026 · завершено после локальной и CI-проверки.

## Поведение

Владелец создаёт Selected users канал, бот передаёт ресурсы, владелец сохраняет и
публикует оформление. Consumer получает только текущие данные опубликованных
блоков. Черновик title/visibility/layout/actions изолирован; откат создаёт новую
версию старого оформления, не откатывая данные. Пустой канал и исчезнувшие
источники имеют явно проверенные состояния. Новый UI ещё не подключён.

## Компоненты

- `channels.py`: draft/preview/publish/rollback, owner inventories, snapshots/ETag.
- Migration 004: immutable `channel_versions`, отдельная draft_visibility,
  published_version, последовательности для списков.
- Общие access/cursors и channel row lock согласуют доступ, публикацию и ingestion.
- Контракт 1.0.3: 74 схемы, 54 planned operations; runtime OpenAPI только реализованное.
- G02: history worker 30 дней вместо 7; тест сохраняет запись на 29-й день и
  удаляет на 31-й. Командные роли запланированы PM-014, проверка PM-023.

[Руководство API](../api/CHANNELS.md) · [ADR-0007](../adr/0007-channel-publication.md).

## Ограничения

Нет Web runtime, действий/SDK/доставки обновлений; это PM-010–018. История версий
хранит оформление, не прежние данные. Версии пока не очищаются. Физическое удаление
и backup recovery ещё не реализованы. Android и облако отложены владельцем.
Docker на этом компьютере не установлен; контейнерная проверка выполняется в CI.
Командные роли обязательны перед внешним пилотом, но ещё не реализованы.
