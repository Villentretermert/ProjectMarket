# PM-014 · B2B Studio and team roles

Accepted 22 October 2026. Product commit `9259c53`, CI setup `b4c26cb`; [CI 39853394634](https://github.com/Villentretermert/ProjectMarket/actions/runs/39853394634) passed all four jobs.

## Implemented

The English Web Studio supports creating a workspace, registering an HTTP bot,
one-time registration/key dialogs, key inventory, immediate rotation/revocation,
seven-day/expired reminders and bot last-seen. The service itself is still created
and operated by its developer; Studio is not a bot-programming environment.

Page editor: source inventory, compatible news/product/chart views, block ordering,
Request purchase binding, title/theme/density, explicit draft save, saved preview,
publish, historical rollback, Selected/Public audience, exact-username read grants,
and shareable channel link. Version conflicts preserve local unsaved form edits.
The preview cannot submit consumer actions from an unpublished layout.

Team UI and server enforce Owner/Admin/Editor. Owner changes membership by existing
username; one permanent Owner is protected. Admin handles bots, keys and audience.
Editor edits/publishes/rolls back within the same audience. Every operation checks
current membership under the organization lock, including private consumer reads
and pending-request reconciliation. A selected workspace header is never permission.
Public or separately granted read access survives removal from the team.

## Code / entities

- Migration `006_teams.sql` expands Membership roles without changing old IDs, adds
  a paging sequence and a unique owner index. Applied migrations 001–005 are unchanged.
- `workspace_access.py` defines the role matrix and organization lock boundary;
  `teams.py` implements workspace/member lists, username upsert and revocation.
- `access.py`, `bot_identity.py`, management routes and `request_state.py` use current
  membership rather than personal-owner assumptions. Resource denial is generic 404.
- Contract revision **1.0.4**, **80 schemas / 59 operations**; bot wire remains 1.0.
  New audience profile route preserves the existing grants response shape.
- `web/studio.js` handles workspaces/bots/keys/team; `studio-editor.js` handles drafts
  and publication using the existing renderer. Credentials have no storage/URL path
  and are cleared when their issuance dialog closes. Async issuance checks account,
  route and visibility before displaying a secret.

## Limits / design differences

Compared with PM-003, Studio now has an explicit workspace selector and team section.
Forms and buttons replace demo toggles. Ownership transfer/multiple owners are not
implemented; this choice was announced before implementation and is documented in
[ADR-0009](../adr/0009-workspace-roles.md). A team member's removal does not invalidate
machine bot keys already issued to that workspace; managers rotate/revoke those keys
separately. Remote UI invalidation still requires Refresh until PM-018; the backend
checks permissions for every request. Android/cloud remain deferred.
