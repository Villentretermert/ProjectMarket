# PM-023-PGDG · Исправление чистой Docker-сборки

24 ноября 2026. [План](../follow-ups/PGDG-ARCHIVE-2026-11-24.md), issue #28.

Первый CI нового исходного дополнения `a084681` обнаружил инфраструктурный
дрейф: PGDG live index больше не содержит `libpq5=18.6-1.pgdg12+2`.
[Неудачный запуск 45396108240](https://github.com/Villentretermert/ProjectMarket/actions/runs/45396108240)
остановился до создания Docker-сервисов; ошибка не относится к PyPI collector.

`deploy/Dockerfile` теперь добавляет официальный `bookworm-pgdg-archive`
перед установкой прежних закреплённых пакетов. `deploy/replacement/Dockerfile`
делает то же для уже выданных старых API images. Существующий keyring PGDG и
обычная проверка подписей apt сохранены, `trusted=yes`/allow-unauthenticated
не добавлялись. Версии libpq5/libpq-dev/OpenSSL не изменены.

Почему: основной PGDG хранит текущие версии; исторические версии находятся
в отдельном `DIST-pgdg-archive`. [FAQ PostgreSQL](https://wiki.postgresql.org/wiki/Apt/FAQ#Where_are_older_versions_of_the_packages?),
[описание архива](https://apt-archive.postgresql.org/).

## Проверка до изменения

Одноразовый контейнер из установленного API image, без пользовательских
volumes и опубликованных ports: `apt-get update -o APT::Update::Error-Mode=any`
проверил подписанный InRelease, оба точных пакета скачаны из архива.

| Файл | SHA-256 |
| --- | --- |
| libpq5_18.6-1.pgdg12+2_amd64.deb | 9dc15f3f41090e632e0449693323f18c96bfd25794c439d8bcde06af6c5012f6 |
| libpq-dev_18.6-1.pgdg12+2_amd64.deb | 9ff4af94d256ef62db43169137d63e9e85de21b048a08e16892f5eb041217f29 |

Версии из dpkg-deb совпали. `libpq.so.5.18` из скачанного пакета побайтово
совпал с библиотекой установленного API. Получатель снова может получить
прежние бинарные inputs; это не доказательство полного offline rebuild.

## Итоговая проверка

Локально исправленный recipient recipe проверен на прежнем API image schema-20261109.
Оба C-расширения пересобрались и загрузили тестовую метку; остальные Python-файлы
и реестр системных пакетов runtime совпали с baseline. Все 13 групп TLS/DB/pool/
rollback/recovery/cancel прошли. [Квитанция](assets/PM-023/pgdg-20261124/replacement.json),
[подтверждение архива](assets/PM-023/pgdg-20261124/archive-probe.json).
Все четыре задания [CI 45396695801](https://github.com/Villentretermert/ProjectMarket/actions/runs/45396695801) на fc40c24 PASS: 314 unit + 111 integration = 425 различных Python-тестов, Web и Docker/HTTPS/HTTP2/backup/restore. На Linux повторный сбор 30 sdists дал тот же SHA-256, что и локальный комплект.
[Квитанция CI](assets/PM-023/python-sources-20261124/ci.json).
Новый кандидат CI проверен; установка новых images в рабочий пилот не выполнялась. Локальный runtime schema-20261109,
БД и source/Docker kits не заменяются. После запуска прежней Docker-службы
четыре рабочих сервиса healthy, API ready/database=ok. PM-023 открыта, 19/24.
