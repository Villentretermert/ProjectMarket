## Изменение

Из Docker API удалён выбор self-contained psycopg-binary3.3.6 с OpenSSL3.5.8.
Выбран поддерживаемый psycopg-c3.3.6, связанный с PGDG libpq18.6-1.pgdg12+2
и Debian libssl3 3.0.22-1~deb12u2. API/мигратор/maintenance используют один образ.
Python API и database.py не изменены. Версия libpq не понижена.

Общий lock сохраняет оба extras; root dev выбирает binary. Docker `--extra c
--no-dev` и `PSYCOPG_IMPL=c` исключают fallback. Headers/gcc остаются в build
stage. Подписанный PGDG источник и ключ взяты из закреплённого официального
postgres18.6 image; точные libpq5/libpq-dev найдены в подписанном apt index.
Сборочный setuptools83.0.0, wheel0.48.0 и packaging26.2 закреплены хешами PyPI.
Psycopg-c sdist содержит C: Cython не потребовался.

[`psycopg` поддерживает local C installation](https://www.psycopg.org/psycopg3/docs/basic/install.html#local-installation).
[`uv` применяет build constraints из root](https://docs.astral.sh/uv/reference/settings/#build-constraint-dependencies).
Версия3.3.7 в [upstream changelog](https://www.psycopg.org/psycopg3/docs/news.html)
на дату проверки остаётся unreleased; обновление номера не выбрано.

## Границы безопасности и совместимости

У исходного Linux binary bundle зафиксирован CVE-2026-84782, но приложение
использует PostgreSQL TCP/TLS, DTLS exploit не воспроизводился. Здесь проверяется
удаление конкретного bundle из Linux поставки; это не утверждение о закрытии
всех CVE приложения или Windows binary. Системный пакет содержит Debian security
backport; номер upstream OpenSSL сам по себе не определяет состояние исправлений.
[Предыдущий анализ](PM-023-psycopg-20261031.md).

PGDG сохраняет GSSAPI/LDAP libraries; DSN приложения не переопределяется.
TLS fixture явно использует gssencmode=disable, чтобы проверить SSL, поскольку
[GSSAPI может иметь приоритет](https://www.postgresql.org/docs/18/libpq-connect.html#LIBPQ-PARAMKEYWORDS).
Kerberos/LDAP infrastructure, arm64 и внешний cloud не проверялись.
Android/Google/полный L2 остаются отложенными. PM-023 не принимается целиком.

246→276 записей всех severity; Critical2→2, High59→60, Medium93→101,

Kerberos/OpenLDAP пакетам:1 High,8 Medium,21 Low. У старого wheel тоже были
bundled Kerberos/LDAP, но сравнение scanner coverage не устанавливает эквивалентность
их security posture. Никакие записи не подавлены; все остаются для разбора.

Новый High CVE-2023-2953 относится к OpenLDAP ber_memalloc_x null dereference.
[Debian tracker](https://security-tracker.debian.org/tracker/CVE-2023-2953)
подтверждает affected Bookworm2.5.13+dfsg-5, no-dsa/minor issue; исправленной
Bookworm-версии в подписанном index нет. Это не объявлено false positive.
Локальный Compose задаёт прямой PostgreSQL host/DSN и не настраивает LDAP service
lookup/Kerberos. Внешние такие конфигурации остаются непроверенными.

Trivy не обнаруживал CVE-2026-84782 в старом psycopg bundle: отсутствие finding
после замены само по себе ничего не доказывает. Удаление bundle подтверждено
[loaded-library inventory](assets/PM-023/psycopg-c-20261101/candidate-inventory.json),
отсутствием binary distribution и системной цепочкой C extension→libpq→SSL.
Остальные base findings, Windows wheel и native consumers не закрыты.
