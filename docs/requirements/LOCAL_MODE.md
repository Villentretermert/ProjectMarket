# Пилот без облачных сервисов

PM-002 · 21 октября 2026. Последний ответ владельца: «пока сделаем на локальном компьютере, без облака». Это уточнение заменяет необходимость создать Firebase сейчас, но сохраняет Google-вход и background push как последующее развитие.

## Текущий объём

- API, данные, worker, Web и пилотные боты работают на компьютере. Android подключается по USB reverse; внешний хостинг не нужен.
- PM-006 реализует локальные учётные записи: имя пользователя, пароль с серверным хешем, отзываемые сессии и logout. Проверки владельца, роли и grants одинаковы для всех клиентов. Секреты/пароли не сохраняются в Git.
- Для разработки предусмотрены Alice (B2B), Bob и Carol (B2C). В PM-002 выбор demo-профиля только показывает экран, не является готовой авторизацией. В продуктовой сборке нельзя подменять сессию выбором произвольного user_id.
- PM-018 обновляет открытое приложение через локальное соединение, восстанавливает пропущенные данные и показывает выбранные события в интерфейсе. Фоновая доставка через FCM/Web Push отложена. Работающий WebSocket не считается push при закрытом приложении.
- Новостной Android-виджет остаётся в пилоте: локальный кеш, время обновления, открытие новости, очистка приватных данных. Обновление в фоне зависит от Android и доступности компьютера; мгновенная доставка в выключенное приложение не обещается.
- API ботов, включая события действий и GET, не зависит от Firebase и сохраняет исходный объём.

## Что отложено

Реальный Google OAuth/OIDC, Firebase/FCM, Web Push провайдер, публичные HTTPS App Links и публичная передача ссылок за пределы локальной сети. В локальном Android spike используется custom-scheme deep link; он не выдаётся за проверенный Android App Link.

Инструкция [Google/Firebase](../setup/GOOGLE_FIREBASE.md) остаётся справочной. Для следующего сетевого этапа потребуются реальные проверки двух Google-аккаунтов, token issuer/audience/expiry, state/nonce/PKCE по выбранному flow, background push и отзыва доступа. Они не отмечаются пройденными локальной имитацией.

Скачивание инструментов и пакетов при сборке использует интернет; работа собранного локального пилота не должна обращаться к внешним identity/push/CDN сервисам. Внешние боты могут иметь собственные сетевые зависимости, не являющиеся зависимостью платформы.

## Граница готовности

Уточнение меняет только требования внешних сервисов. Web/Android, настоящий домашний виджет, изоляция данных, тесты, Docker и презентации остаются обязательными. PM-002 не закрывается до фактического доказательства клиентского стека.
