# Пользовательские сценарии MarkeTOB

PM-001 · 21 октября 2026 · нормативное описание пилота; это сценарии будущей приёмки, не пройденные продуктовые тесты.

## US01 — B2C читает витрины

Пользователь открывает Channels, выбирает магазин или новости и видит карточки/график со временем обновления. Состояния Loading, Empty, Offline, Access required и Error имеют текст и безопасное восстановление.

## US02 — Пользователь входит локально

В пилоте без облака User имеет локальную учётную запись и отзываемую серверную сессию. Роли B2B/B2C могут совмещаться. Персональные операции требуют входа; вход не создаёт права на произвольную закрытую страницу. Google identity отложена; будущая связь с User не должна основываться только на совпадении email. См. [LOCAL_MODE.md](LOCAL_MODE.md).

## US03 — B2B подключает своего бота

В Studio новый владелец создаёт workspace, bot и bootstrap credential. Бот однократно обменивает его на рабочий ключ. В UI ключ виден один раз; другие боты/владельцы не доступны.

## US04 — Бот публикует данные

Независимый HTTP-процесс шлёт text/data/event. API проверяет bot/tenant/schema, сохраняет snapshot+outbox атомарно. При повторе message_id бизнес-состояние не дублируется.

## US05 — B2C отправляет заявку, бот отвечает

Кнопка Send request → server action_request → GET события конкретным ботом → durable receipt/ACK → бизнес-результат. Pending не называется подтверждённой покупкой. Неоднозначный timeout даёт status unknown, а не повторное списание.

## US06 — B2B публикует страницу

Владелец связывает разрешённые блоки с данными, проверяет preview, публикует неизменяемую версию и делится ссылкой. Откат меняет опубликованный шаблон, не отменяет уже выполненные заявки.

## US07 — B2B управляет закрытым доступом

Рабочее решение пилота: доступ выдаётся уже зарегистрированным локальным пользователям по user handle/ID. Приглашения на произвольный email отложены. Отозванный grant блокирует чтение/действие/live; UI очищает закрытый кеш.

## US08 — B2C сохраняет канал

Save channel добавляет контактоподобный элемент в список. Повтор идемпотентен. Избранное принадлежит User и синхронизируется между Web/Android; удаление не удаляет источник.

## US09 — B2C создаёт My Space

Выбирает блоки минимум из двух каналов, меняет порядок, ограниченные theme tokens и совместимый вид, сохраняет layout. Данные продолжают обновляться из источников; редактор не меняет B2B страницу.

## US10 — Друг импортирует интерфейс

Автор создаёт immutable snapshot layout+bindings и короткий код. Друг видит preview, импортирует отдельную копию. Никакие grants, bot keys или payload источника не копируются; недоступный источник отмечается явно.

## US11 — Клиент получает обновления

Открытый клиент получает live сигнал и читает новую разрешённую revision. После reconnect выполняет resync. В локальном пилоте выбранные события отображаются внутри открытого клиента. Background push отложен до включения внешнего провайдера; он не имитируется WebSocket-соединением.

## US12 — B2C ставит новостной виджет

Выбирает свой доступный news source. Виджет показывает заголовки/время, открывает новость и учитывает ограниченную частоту ОС. После logout не хранит закрытый контент; при отсутствии связи TTL очищает приватный кеш.

## US13 — Владелец запускает пилот локально

Компьютер запускает API/worker/БД/Web; телефон подключается через документированный USB reverse или доверенную LAN-конфигурацию. Секреты остаются на сервере. Пилот не публикуется автоматически в интернет. APK/AAB и переносимый Docker остаются целью.

## US14 — Разработчик воспроизводит интеграцию

Берёт английские OpenAPI, JSON Schema, Python SDK и quickstart, отправляет первое сообщение и обрабатывает GET action. Каждая задача имеет пояснения и тестовые доказательства.

## US15 — Оператор измеряет нагрузку

Запускает малый локальный smoke, затем масштабный профиль с 100 bot identities, 1 000 msg/min и отдельно заданной concurrency. Отчёт указывает hardware, payload, latency, ошибки и пределы; MAU не превращается в RPS.

## US16 — Команда расширяет платформы позже

Стабильные схемы и backend допускают iOS/Windows; их сборки/виджеты имеют отдельные задачи и не объявляются готовыми в Android/Web пилоте.

## Сквозной разбор двумя ролями

**B2B Alice:** US02 → US03 → US04 → US06 → US07. Alice владеет workspace A, публикует публичный каталог и закрытую ленту. Bob не может подставить workspace A в свой управляющий запрос. Рабочий ключ бота A не разрешает чтение/запись бота B.

**B2C Bob:** US01 → US02 → US08 → US05 → US09 → US10 → US12. До grant закрытая лента недоступна; после grant Bob добавляет её в My Space. Импорт этого layout пользователем Carol не наследует grant. После отзыва grant Bob получает Access required, action отклоняется, подписка закрывается, online cache очищается. Offline/private widget cache скрывается при истечении TTL.

**Сбой:** бот сохранил действие, но ACK потерялся → повтор GET возвращает event → бот распознаёт устойчивый action_request_id → не создаёт второй заказ. ACK без result остаётся Processing до timeout/reconciliation. Данные UI не определяют окончательную цену/доступность — решение делает бот по проверенному resource_id.

**Обмен:** Share layout создаёт snapshot, автор позже меняет страницу, импортированный layout Bob не меняется. Данные разрешённого источника продолжают обновляться. Отзыв share code запрещает новые импорты, а не удаляет существующие копии.

## Рабочие UX-решения для первого этапа

Публичный preview без входа; персональные операции после локального входа. Закрытые grants выдаются уже зарегистрированным пользователям. Статус заявки обновляется автоматически. Эти решения выбраны для минимального связного пилота, не приписываются ответам владельца; могут быть пересмотрены в G01 без изменения обязательной изоляции данных.
