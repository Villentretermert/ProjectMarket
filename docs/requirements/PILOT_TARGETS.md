# Цели и ограничения локального пилота

PM-001 · 21 октября 2026. Числа ниже — **инженерные цели для проверки**, не измеренная производительность и не новые ответы владельца. Менять через DECISIONS/CHANGELOG; фактические измерения PM-012/022.

## Профили запуска

| Профиль | Нагрузка | Назначение |
|---|---|---|
| L0 local smoke | 2 бота, 2 Google-пользователя, 1 браузер + 1 Android; 10 msg/min | Воспроизводимость главных сценариев на компьютере владельца |
| L1 local baseline | 10 ботов, 10 активных клиентов, 100 msg/min, 15 минут | Проверка локальной разработки и восстановления |
| L2 scale target | 100 bot identities, 100 активных клиентов, 1 000 msg/min, 30 минут | Целевой профиль пилотной архитектуры; только после фиксации CPU/RAM/диска и объёма данных |
| Burst | 3 000 msg/min в течение 60 секунд после L2 | Проверка backpressure/429 и восстановления очереди без потери принятых сообщений |

10 000 MAU — месячный продуктовый ориентир; из него не выводится число одновременных сессий. 100 одновременных клиентов в L2 — выбранный тестовый параметр, который можно пересмотреть по наблюдениям. Если компьютер не тянет L2, отчёт показывает реальный предел; требование не считается автоматически выполненным.

Для профилей по умолчанию: 80% news/product upsert до 4 KiB, 20% chart до 32 KiB; 10% клиентов создают одно действие/мин. Принятые сообщения считаются только после durable подтверждения. Тест фиксирует версии ПО, hardware, сеть, размеры БД и длительность.

## SLO

| ID | Цель при L1/L2 | Измерение |
|---|---|---|
| SLO-LIVE | p95 ≤ 3 с; p99 ≤ 10 с | От успешного durable приёма backend до отображённой revision на открытом клиенте в доступной сети |
| SLO-READ | p95 ≤ 500 мс; p99 ≤ 2 с | Серверная обработка разрешённого чтения канала; отдельно от старта браузера |
| SLO-INGEST | p95 ≤ 500 мс; p99 ≤ 2 с | POST до durable receipt; отдельно считать rate-limit ответы |
| SLO-ACTION | p95 ≤ 3 с до доступности события в GET | От записи заявки до первой доступности для подключённого бота; время бизнес-операции бота отдельно |
| SLO-RECONNECT | актуальный snapshot ≤ 10 с после восстановления связи | Проверка пропуска live-событий и cursor resync |
| SLO-DURABILITY | 0 потерянных подтверждённых сообщений | Сверка message_id после рестарта API/worker; защита от потери всего диска требует backup |
| SLO-ERROR | <1% непреднамеренных 5xx в steady state | Невалидные запросы и ожидаемые 429 учитываются отдельно, не маскируют 5xx |

Для push фиксируется server enqueue/provider acceptance latency; доставка устройству зависит от сети/ОС/провайдера и измеряется отдельно. Нет обещания push за 3 секунды или обновления домашнего виджета каждую секунду.

## Начальные пределы контракта

Рабочие значения для PM-004: тело сообщения ≤256 KiB; до 50 блоков страницы; до 1 000 точек на chart-series, до 5 серий; GET событий page limit 100; long-poll ≤25 секунд; item text ≤20 000 символов. Retry-After обязателен для 429. Большие изображения не встраиваются Base64 в JSON; media policy уточняется в контракте.

## Хранение и приватность

| Данные | Рабочая политика пилота |
|---|---|
| Актуальная запись бота | До явного удаления владельцем/ботом; deleted/tombstone поддерживает resync |
| Raw ingest payload/history | 7 дней; не является бессрочным архивом |
| Message idempotency receipts | 30 дней; повтор за пределами окна не имеет гарантии дедупликации |
| Незавершённые actions/events | До terminal/reconciliation/явного timeout; не удалять лишь по возрасту до разрешения статуса |
| Terminal actions/results | 30 дней, затем минимизация/удаление по документированной политике |
| Audit без payload/секретов | 90 дней |
| Локальные резервные копии | Ротация 7 дневных копий; восстановление проверяется в PM-021 |
| Private offline cache/widget | Максимум 15 минут без повторной проверки доступа; затем скрыть; logout очищает сразу |
| Public cache | Можно показать устаревшее с временем; action требует online revalidation |

Удаление аккаунта/источника отзывает доступ и останавливает новые действия немедленно; очистка active storage ≤24 часов, следы в rotating backups ≤7 дней. Эти сроки — рабочее проектное ограничение пилота, не юридическое заключение; destructive cleanup требует доказанного сценария и отдельной реализации PM-023.

## Открытые вводные и место решения

- Облачные регион, бюджет и домен: **отложены** до запроса на перенос. Local-only не зависит от покупки сервера.
- Docker runtime и WSL2: проверка/настройка до PM-005/021. Docker сейчас не обнаружен; это не означает невозможность локального Python-прототипа.
- Android: владелец подтвердил наличие телефона; actual model/OS/launcher/USB permissions фиксируются при подключении в PM-002.
- Google/Firebase: проекта пока нет; владелец создаёт его по инструкции PM-002. Реальный вход и push нельзя зачесть по заглушке.
- Скорость cold start, размер APK/Web, offline/доступность: измерения PM-002; пороги выбираются по сравнимым прототипам.
- Форматы grants, media, retry и compatible visualization окончательно фиксируются PM-004; правила доступа из требований не ослабляются.
