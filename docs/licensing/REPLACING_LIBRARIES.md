# Замена psycopg-c получателем поставки

7 ноября 2026. Проверенный сценарий предназначен для Linux amd64 API пилота
68958f1, Python 3.14.9, psycopg-c 3.3.6 и libpq 18.6. Он собирает изменённые
C-исходники и проверяет их в отдельном образе. [Фактический результат](../task-results/PM-023-replacement-20261107.md).

## Что подготовить

Нужны checkout MarkeTOB с этой инструкцией, Python 3.14, работающий Docker и
локальные образы API и БД. Образы можно получить через `docker load` из поставки
либо собрать по [инструкции локального запуска](../setup/LOCAL_DELIVERY.md).
Сверьте их идентификаторы с реестром соответствующей поставки.

Для повторения проверки установленного пилота использованы следующие ID.

| Образ | ID |
| --- | --- |
| API | `sha256:7a25ca664062d8f81018757e1cb542653536143971a6f5d73bcca9b10c17728b` |
| БД | `sha256:07aa878e696f9eca7e46515ba052c6f80f1372d09686cfb7b71ba49054b5a52f` |

[Комплект Python/Rust](../../third_party/68958f1-crate-notices/README.md) содержит
`psycopg_c-3.3.6.tar.gz`. Его SHA-256 должен совпасть с
`29c568426ad61c1b702c7d73505c43ca2c9fc5d97a8431d8d9049e731e319ff8`.
Программа проверяет хеш из `uv.lock` до распаковки. Вместо локального файла
можно использовать `--fetch` для загрузки того же архива из PyPI.

Сборка требует сети для Debian/PGDG build tools и трёх Python build dependencies.
setuptools, wheel и packaging закреплены версиями и хешами в `pyproject.toml`.
Компилятор выбирается из подписанного APT-репозитория. Фактический список
build-пакетов сохраняется внутри тестового образа. Это повторяемый процесс
проверки замены, побитовое воспроизведение исходного wheel им не устанавливается.

## Повторить проверку

Из корня checkout выполните следующую команду. Каталог результата должен быть
новым и находиться внутри `.local`. Подставьте имена загруженных образов или их ID.

```text
python -m scripts.replace_psycopg --api-image marketob-api:68958f1 --db-image marketob-db:d53232e --fetch --output .local/recipient-replacement
```

На Windows с Docker в Ubuntu WSL добавьте `--wsl Ubuntu`. Для локального
исходного архива замените `--fetch` на `--source <путь-к-psycopg_c-3.3.6.tar.gz>`.

Сценарий дописывает в два C-файла функцию `marketob_recipient_build()`, собирает
wheel и устанавливает его в производный образ. Функция возвращает тестовую метку.
Изменения помечены датой и LGPL-3.0-only, исходный LICENSE.txt сохраняется.
Приложение затем импортирует оба расширения. Проверка вызывает метку через
дескрипторы уже загруженных библиотек и требует изменения их SHA-256.

Далее сравниваются байты остальных файлов site-packages и реестр системных
пакетов, проверяются UID 10001, C implementation и libpq 18.6. Одноразовая БД
работает во внутренней Docker-сети с временными сертификатами, без опубликованных
портов. Проверяются TLS, JSONB, оба пула приложения, commit/rollback, timeout,
восстановление соединений и cancel_safe. После проверки её контейнер, сеть
и том сертификатов удаляются.

## Результаты и собственные изменения

В выбранном каталоге сохраняются следующие материалы.

| Файл | Назначение |
| --- | --- |
| original.tar.gz | Проверенный исходный архив |
| modified-source.tar.gz | Полное дерево с двумя отмеченными изменениями |
| modification.json | Хеши исходника, лицензии и изменённых C-файлов |
| context/ | Dockerfile, build requirements и редактируемые исходники |
| context.tar | Контекст, фактически переданный Docker |
| build.log, smoke.log | Результаты компиляции и проверки с БД |
| result.json | ID образов, метки, хеши, linkage и итог PASS |

Итоговый образ получает отдельное имя `marketob-replacement:<случайный-id>`.
Его wheel и перечень build-пакетов лежат в
`/usr/local/share/marketob-replacement/`. Программа печатает тег и каталог
результата. Рабочие сервисы пилота не переводятся на этот образ.

Для своей модификации отредактируйте C-файлы в `context/source` и соберите
`context/` с Docker CLI в Linux. Сохраните интерфейс и версию, совместимые
с установленным psycopg. Укажите отдельный тег своей сборки.

```sh
docker build --build-arg API_IMAGE=marketob-api:68958f1 --tag marketob-recipient:custom .local/recipient-replacement/context
python -m scripts.smoke_psycopg --api-image marketob-recipient:custom --db-image marketob-db:d53232e
```

Эти две команды проверяют вашу модификацию теми же сценариями БД. Проверка метки
и полный сравнительный result.json относятся к автоматическому демонстрационному
прогону. Для остальных зависимостей потребуются их рецепты сборки и отдельные
проверки ABI и приложения. Условия передачи всей поставки перечислены в
[общем перечне](DISTRIBUTION.md).

[Официальная инструкция psycopg](https://www.psycopg.org/psycopg3/docs/basic/install.html#local-installation)
описывает сборку C-расширения с системным libpq. [Лицензия psycopg 3.3.6](https://github.com/psycopg/psycopg/blob/3.3.6/LICENSE.txt)
сохраняется вместе с исходниками и wheel. Проверенный здесь механизм замены
является одним инженерным результатом подготовки поставки.
