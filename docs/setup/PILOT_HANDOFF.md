# Локальный Web-пилот · инструкция владельцу

24 октября 2026 · независимая подготовка PM-024. Это инструкция для уже
работающего пилота и последующей приёмки candidate, **не принятый release candidate**.
Завершено 19/24 задач; [текущий статус](../STATUS.md) имеет приоритет.

## Пользователь

Откройте [MarkeTOB](http://127.0.0.1:19000/app/), выберите Create account и создайте
локальный аккаунт. Google/Firebase сейчас не нужны. После входа открывается
My Space. По ссылке B2B откройте канал, добавьте его в Favorites и задайте порядок.
На My Space соберите блоки доступных каналов, выберите визуализацию, переместите
блоки; изменения сохраняются автоматически, Undo создаёт новую версию.

В каталоге Request purchase сначала показывает товар, одну единицу и отсутствие
списания денег. Confirm отправляет заявку, Check status проверяет существующую.
Awaiting confirmation означает неизвестный окончательный исход, а не отказ:
повторную покупку для проверки статуса создавать не нужно.

Share передаёт оформление и ссылки. Друг импортирует самостоятельную копию;
закрытые источники останутся недоступными без отдельного разрешения их владельца.
Подробнее: [Web](WEB.md), [Favorites](FAVORITES.md), [My Space](MY_SPACE.md),
[Share/Import](SHARING.md), [Events](LIVE_UPDATES.md).

## B2B и разработчик бота

В Studio создайте workspace, зарегистрируйте бот и передайте одноразовый
credential только своему сервису. Сервис меняет его на рабочий ключ, после чего
отправляет данные по HTTP API. Ключ показывается один раз; сохраните его в
приватной конфигурации сервиса. Создайте страницу, настройте блоки, сохраните
draft, проверьте Preview и Publish. Default audience — Selected users.
Доступ выдаётся точному username зарегистрированного пользователя.

Owner управляет командой; Admin управляет ботами/ключами/доступом; Editor оформляет,
публикует и откатывает страницы. Бот работает отдельным процессом и не получает
прямого доступа к БД MarkeTOB. Инструкции:
[Studio](STUDIO.md), [Python SDK](../../packages/bot-sdk/README.md),
[протокол и схемы API](../api/PROTOCOL.md), [два пилотных бота](PILOT_BOTS.md).

Для отдельного синтетического опыта на текущем сервере можно подготовить новую
пару ботов из корня репозитория (выберите ещё не занятый username и новый каталог):

```powershell
.venv-dev/Scripts/python.exe -m scripts.pilot_bots --url http://127.0.0.1:19000 --username demo_owner --create-account --directory .local/handoff-demo --offline
.venv-dev/Scripts/python.exe -m marketob_bots.catalog --env-file .local/handoff-demo/catalog.env
```

Пароль вводится скрыто по запросу. Пока каталог работает в первом терминале,
во втором запустите новости:

```powershell
.venv-dev/Scripts/python.exe -m marketob_bots.news --env-file .local/handoff-demo/news.env --offline
```

Ссылки каналов находятся в `.local/handoff-demo/channels.json`. Не запускайте
команды повторно с новым журналом для уже работающего бота. Для реальной публичной
RSS уберите `--offline` у news; адрес задаётся в его приватном env. Команды выше
создают данные, поэтому предназначены для осознанного ручного опыта владельца;
при подготовке этой инструкции новые аккаунты на рабочем пилоте не создавались.

## Повторяемая приёмка двумя аккаунтами

Используйте обычное и приватное окна браузера для Owner и Reader. Пароли/ключи
не включайте в протокол проверки. Для отказа доступа нужен Reader вне команды;
добавление в команду может давать отдельное право чтения.

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Owner запустил catalog/news; Reader зарегистрировался | Два независимых бота, два аккаунта |
| 2 | Reader открывает Selected users ссылку до grant | Частные заголовки и данные не показаны |
| 3 | Owner выдаёт read grant Reader и обновляет товары | Reader видит публикацию; новые данные приходят в открытом Web |
| 4 | Reader запрашивает Hand soap, затем Paper towels | Confirmed и демонстрационный Failed; деньги не списываются |
| 5 | Reader добавляет каталог/новости в My Space, меняет порядок/вид, Undo | Layout сохраняется после повторного входа |
| 6 | Reader делится layout; Owner импортирует | Самостоятельный layout, доступ проверяется для каждого источника |
| 7 | Owner отзывает read grant у Reader при открытом подтверждении товара | В candidate PM-023 диалог закрывается, частный контент исчезает, заявка не отправлена |
| 8 | Вкладка теряет сеть, затем сеть возвращается | Частные данные скрыты; восстановление повторно проверяет права |
| 9 | Owner отзывает/заменяет ключ одного бота | Старый ключ отклоняется; второй бот продолжает работу |
| 10 | Оператор выполняет backup/restore в отдельную БД | Проверены checksum, миграции и контрольные данные, исходная БД сохранена |

Записывайте дату, commit/tag, browser и факт PASS/FAIL каждого шага. Автоматический
аналог первых девяти направлений — `scripts.smoke_web`; новые privacy-проверки в
[отчёте D46](../task-results/PM-023-account-privacy.md), прежние результаты в
[PM-023](../task-results/PM-023.md). Шаг 7 исправлен в исходниках candidate;
работающий Docker на `6b3ffb5` ещё не содержит этой правки. Ручная приёмка
владельцем по этой таблице пока не выполнялась.

## Оператор и известные ограничения

[LOCAL_DELIVERY](LOCAL_DELIVERY.md) содержит запуск/остановку существующего
`marketob-pm021`, чистую установку, теги и безопасный откат.
[BACKUP_RESTORE](BACKUP_RESTORE.md) — отдельную БД для восстановления;
[OPERATIONS](OPERATIONS.md) — метрики, alerts, бюджеты и диагностику.
Не используйте `down --volumes` на данных пилота. `.env`, журналы ботов и backups
не входят в Git. Удаление аккаунта пока означает деактивацию согласно
[описанию данных](../privacy/DATA_POLICY.md).

| Gate выпуска | Состояние |
| --- | --- |
| Web/API/worker, локальный Docker, restore/HTTPS | Базовая поставка принята в PM-021; candidate проверяется отдельно |
| Полная 30-минутная нагрузка 100 клиентов | PM-022 отложена владельцем до свободного компьютера |
| Приватность/экспорт/удаление | PM-023 частично; открытые решения и проблема полной очереди |
| Android APK/AAB, USB, домашний виджет | PM-019/020 отложены владельцем |
| Google/Firebase, background push, Play | Отложены; локальный login/in-app Events не заменяют эти проверки |
| G05, сквозная приёмка и RC | Не выполнены, PM-024 остаётся открытой |

Доступ сейчас ограничен этим компьютером. Публичный адрес, LAN-доступ телефона,
облачный сервер и публикация в Play этой инструкцией не включаются.
