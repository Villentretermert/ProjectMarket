## Достоверность и границы

Источники проверены по коду и документации на commit
`11653f0a81f5911076ddedc473bbc60e63909d70`.
Тестовая запись использует закреплённые образы schema-20261109 и приложение
`896449bde9cdec4cea9f7ce29eba6910285da30e`.
Позднейшие коммиты в основном относятся к поставке, зависимостям и проверяемости исходников.

В видео настоящие Web, API, PostgreSQL и два Python-бота. Аккаунты, товары и RSS
синтетические. Статус Confirmed проходит через API и бота. Показаны экраны privacy
и ключей, но удаление аккаунта и выдача секрета не выполняются. Видео без звука,
с русскими пояснениями поверх английского UI.
Длительность 2:47, 1440 × 1000, H.264, 5,17 МБ. Полное декодирование
и визуальная проверка кадров всех 23 глав пройдены.

Скриншоты взяты из успешного дубля take-03; три экрана My Space заменены
более наглядными кадрами take-04. Финальное видео использует take-04.
Оба дубля работают на одинаковых закреплённых образах в раздельных временных средах.

Android APK/AAB, настоящий домашний виджет, Google/FCM, облако, полный L2,
внешний пилот и итоговая PM-023/024 остаются непринятыми или отложенными.
514 Python-тестов и 69 browser checks относятся к ранее завершённому
[CI 45421327206](https://github.com/Villentretermert/ProjectMarket/actions/runs/45421327206),
а не к новому полному прогону ради документации.

PM-023-ALPATTR остановлена переключением на этот запрос. Её план сохранён
в [отдельном файле](../../follow-ups/ALPINE-ATTRIBUTION-2026-11-24.md), результат не заявлен.

## Проверка и воспроизведение

Все 68 слайдов отрисованы в 1280 × 720 и просмотрены по отдельности. Проверены
длинные заголовки, таблицы, текст и стрелки. По итогам исправлены оглавление,
направление HTTP-запросов, разделение maintenance/backup, связь личной страницы
с источником, маршрут обмена ключа и ветка отмены до ACK. Заметки ссылаются
на проверенный commit; новый план Alpine ссылается на актуальную ветку.

Видеозапись проверяет открытие двух каналов, избранное, два блока разных источников,
Card, autosave, reorder, Undo, подтверждение заявки и итог Python-бота. В БД
должна остаться ровно одна confirmed-заявка. Временный Docker-проект удаляется
в `finally`; пользовательская рабочая база не используется.

Для повторной записи нужны установленный проверенный комплект образов, WSL Ubuntu
с Docker, окружение Python проекта и Playwright из `apps/client`.
Команда выполняется **из корня ProjectMarket**:

```powershell
$env:MARKETOB_BROWSER_CHANNEL = 'msedge'
& .venv-dev/Scripts/python.exe -X utf8 docs/reviews/PROJECT-2026-11-24/record_demo.py --wsl Ubuntu --output .local/project-review-repeat
```

Сценарий создаёт только отдельную среду и тестовые учётные записи. Данные входа
передаются в recorder через stdin и не входят в отчёт. Конвертация в MP4 использует
временный FFmpeg из imageio-ffmpeg 0.6.0; инструмент не добавлен в зависимости приложения.
