# ADR-0001 — Web-клиент и отложенная проверка Android

Дата: 21 октября 2026. **Web: принято. Android: решение открыто.** PM-002.

## Контекст и изменение объёма

Владелец требует максимум Python, но разрешил другие языки для качества UI/виджетов. Затем выбрал локальный запуск без облака и явно ответил «Пока отложить Android-сборку» / «Подключу позже». Поэтому текущая приёмка PM-002 ограничена Web и архитектурой; доказательство APK/виджета перенесено в начало PM-019/020. Android не считается проверенным этим ADR.

## Практическое сравнение

Оба spike показывают товар, новости, числовую серию, избранное, demo-профиль и маршруты. Данные синтетические, backend отсутствует.

| Проверка | Flet 1.0.4 / Python 3.14 | Семантический HTML/JS + Capacitor 8.4.3 |
|---|---|---|
| Браузерный экран | Динамический Python-сервер: работает | Статический bundle: работает |
| Избранное / вид графика после reload | Подтверждено в браузере | Подтверждено в браузере |
| Доступность | После Enable accessibility доступны кнопки; текстовые строки графика сгруппированы | Заголовки, кнопки, подписи SVG, настоящая таблица доступны сразу |
| Offline runtime | Динамическая сессия зависит от сервера; не offline | После первого открытия: reload и переход к новостям при остановленном сервере прошли |
| Статическая сборка | `flet build web` завершился ошибками Dart hooks; `flet publish --no-cdn` создал файлы, но старт упал на `pyodide/pyodide.mjs` | `npm ci` / `npm run build`; автономные файлы без CDN |
| Размер файлов на диске | `flet publish`: 76 291 446 байт, 86 файлов, до дополнительных Python dependencies | Около 21 KB, 4 файла; точные размеры в отчёте |
| Android | Не собирался | Gradle-проект и Java-мост виджета подготовлены; не собирался |

Размеры не равны сетевому трафику первого открытия или размеру APK. Время запуска не измерялось надёжным benchmark; визуальное открытие не подменяет такой замер. Обнаруженные ошибки относятся к проверенной связке и Windows-путям, не доказывают невозможность Flet вообще. Для динамического Flet пришлось закрепить FastAPI 0.135.1 и Starlette 0.50.0; backend проекта не обязан наследовать эти версии.

## Решение

Web runtime — HTML/CSS и модульный JavaScript с минимальной сборкой esbuild. Python остаётся языком backend, схем, SDK, ботов и большинства проверок. На этапе PM-013 UI разбивается на компоненты по контракту; backend определяет доступ и бизнес-результаты, браузер не исполняет присланный ботом код.

Capacitor — кандидат для упаковки того же Web runtime в Android. Для AppWidget нужен нативный provider; в spike используется Java, совпадающая с шаблоном Capacitor и не требующая ещё одного компилятора. Нативный код ограничивается системной интеграцией. Подготовлены `NewsWidgetPlugin`, `NewsWidgetProvider`, XML layout и custom-scheme deep link. Это исходники, не доказательство работающего APK.

До окончательного Android-решения обязательны: SDK-лицензия владельца, сборка, установка, offline cold start, переход из настоящего launcher-виджета, обновление/очистка кеша и повторное открытие. Если эти проверки не пройдут, Android-оболочка пересматривается; Web/API контракты сохраняются. iOS/Windows остаются последующими задачами.

## Последствия

Python UI не выбран для Web после практического сравнения. Это оправданное исключение из приоритета Python: небольшой автономный клиент, доступность и меньше обязательных runtime-зависимостей. Service worker spike кеширует только публичную оболочку; приватные API данные в него добавлять нельзя. Google, FCM и публичные App Links сейчас не требуются.
