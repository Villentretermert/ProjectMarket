# ADR-0017 · Personal export and ownership before deletion

24 октября 2026. Основание: ответы D46, независимая Web/API-часть PM-023.

Состав экспорта, передача workspace перед удалением и пароль + DELETE выбраны
владельцем. Вместо прежнего выключения B2B workspace удаление теперь блокируется
до передачи. Один Owner на workspace и один собственный workspace на аккаунт
сохраняются; существующие Admin могут стать владельцем. Это дополняет ADR-0009,
не переписывает применённые миграции. Миграции не требуются.

Передача — один POST от Owner с текущим паролем, транзакционное обновление
organizations/memberships и marker ADR-0016. Прежний владелец остаётся Admin.
Проверка активного получателя под блокировкой user предшествует workspace lock;
delete и business-profile используют ту же границу user→workspace. Ошибки БД
не превращаются в успех; уникальные ограничения защищают одного владельца.
При конфликте/потере ответа клиент перечитывает фактические роли.

Экспорт — явные проекции собственных данных. Большие разделы разбиты на страницы
с фиксированным верхним sequence и session-bound cursor. Это сохраняет небольшие
HTTP-транзакции и не держит БД открытой на время скачивания. Альтернатива одного
неограниченного JSON или долгой streaming-транзакции отклонена из-за памяти и
блокировок. Цена решения: экспорт живой, не единый snapshot. Web собирает файл
только после всех страниц, до50MiB; API доступен для больших выгрузок.

Удаление физически убирает личную настройку и shared links. Ранее импортированные
копии другого пользователя независимы. Username/ID tombstone и заявочные записи
сохраняют установленные правила reconciliation/retention; никакого обещания
сквозного удаления из внешних ботов/backups нет. Это инженерная реализация
удаления личных данных в заданной пользователем модели, не юридическое заключение.

Контракт1.1.0 явно отмечает несовместимое требование confirmation и новую409 для
владельца; Bot API/wire1.0 не меняется. Тестовые smoke-сценарии больше не используют
удаление владельца как способ выключить workspace: отзывают тестовых ботов,
завершают сессию, а строки остаются в disposable БД до её очистки.

Проверки и действующий статус: [отчёт](../task-results/PM-023-account-privacy.md).
Android, виджет, Google/Firebase, cloud и полный L2 остаются отложенными.
