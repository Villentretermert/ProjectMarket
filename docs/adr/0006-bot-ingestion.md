# ADR-0006 · Реестр ботов и транзакционный приём

22 октября 2026 · принято технически в PM-007/008; не новый ответ владельца.

HTTP-сервис бота получает отдельный одноразовый bootstrap и operational key.
Оба содержат 256 случайных бит; в БД хранится SHA-256 verifier. Для таких случайных
значений медленный password hash не нужен; пользовательские пароли остаются Argon2id.
Разные prefixes предотвращают смешение типов credential. Raw secret показывается
только при выдаче, rotation отзывает старый ключ в той же транзакции.

Вместо отдельного брокера в локальном пилоте выбран PostgreSQL outbox. Текущая
запись, tombstone, квитанция, channel data_revision, raw history и update hint
фиксируются одной транзакцией. Альтернатива «сначала БД, потом отправить событие»
оставляла бы окно потери события. Получатель outbox реализуется последующими задачами.

Блокировка bot row сериализует запросы одного бота и его message_id между каналами.
Порядок: organization → bot → key → channel. Это упрощает atomic revoke/replay
и защищает от двух успешных bootstrap exchanges. Цена — ограниченная параллельность
одного бота; пилотная квота 60 сообщений/мин делает решение приемлемым для проверки.
При расширении нагрузки переходить к более узким lock keys после измерений.

Проверка исходной JSON Schema выполняется до persistence, без преобразования
payload через coercing models. SHA-256 от канонической JSON-строки игнорирует
порядок ключей, но сохраняет различие 1/1.0. Postgres jsonb хранит данные; fingerprint
считается до преобразования в jsonb. Нет исполнения присланных выражений или HTML.

Квоты ingestion — отдельная короткая транзакция token buckets: общий bucket перед
bucket бота, commit также при отказе. История ограничена 7 днями, квитанции 30;
maintenance — отдельный Python-процесс в Compose/локальном запуске. Он не является
очередью бизнес-действий PM-010 и не обрабатывает пользовательские заявки.

Draft-create включён в PM-008 как минимальный путь подготовки источника без ручного
SQL. Layout редактирование, публикация и snapshot чтение сохраняются в PM-009.
100 HTTP сообщений/4 бота измерены отдельно; устойчивые SLO остаются в PM-022.
