# ADR-0003 — Bot API 1.0: snapshots и доставка действий

21 октября 2026 · PM-004 · принято как технический контракт, runtime ещё не реализован.

## Решение

OpenAPI 3.1.1 + JSON Schema 2020-12, генератор/модель/проверки на Python. Сообщения заменяют типизированный snapshot с монотонной source_revision; сервер отдельно назначает data_revision. Страница имеет независимую template_version. Не принимаем произвольный исполняемый интерфейс.

GET событий не меняет состояние доставки. Ограниченный scan с верхней границей и cursor возвращает unACKed события; после конца scan потребитель начинает новый. ACK — только надёжное получение, result — отдельный бизнес-результат. Незавершённые ACKed заявки доступны через reconciliation GET. Доставка at-least-once требует дедупликации у бота. Отзыв доступа до ACK отменяет заявку; после ACK требует выяснения фактического результата.

Для локального foreground-клиента v1 выбирает polling каждые 2 секунды и revision hints. Это рабочая частота, не замер SLO. SSE можно добавить позднее без изменения snapshot/action semantics. Облачный push не нужен для этой версии.

## Альтернативы и последствия

Удаление события при GET теряло бы заявки при падении потребителя. Lease через GET делал бы чтение изменяющей операцией и усложнял восстановление. Webhook требует входящего адреса бота и не заменяет обязательный GET. Exactly-once для внешних бизнес-эффектов не обещается: нужен устойчивый ключ или статус внешней операции.

Серверные share-коды сохраняют immutable оформление/ссылки; код не является шифрованием или разрешением читать источник. Ограничения typed JSON проще проверить и реализовать в двух клиентах, но новые блоки, валюты и media потребуют явного расширения контракта.
