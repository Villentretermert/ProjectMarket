- **Порядок:** 6; этап 2 — Основа, доступ, боты и данные.
- **Приоритет:** P0.
- **Состояние:** planned.
- **Зависимости:** PM-004, PM-005, G01.
- **Открытые вводные:** использовать зафиксированные решения; новые блокеры описывать явно.

## Цель

Создать общую модель пользователя и изоляцию владельцев/читателей.

## Объём и порядок работы

1. Прочитать регламент, решения, зависимости и связанную GitHub issue.
2. Реализовать Google OIDC на Web и контракт Android, безопасные сессии, logout/revocation, организации и членство, самостоятельное получение B2B роли. Публичные и закрытые страницы имеют разные правила; выбранным Google-пользователям выдаётся явный доступ. Проверять права на объект на сервере. Определить политику email приглашений и удаление аккаунта.
3. Выполнить критерии ниже, обновить документацию и пояснительную записку.

## Ожидаемые результаты

Миграции пользователей/организаций/grants, auth API и документация.

## Критерии приёмки

- [ ] Подделанный, просроченный или выпущенный для другого клиента токен отклоняется. Tenant/роль не берётся из неподтверждённого ввода. B2C не редактирует B2B контент; выход отзывает сессию.
- [ ] Проверки выполнены и их фактические результаты сохранены.
- [ ] CHANGELOG, STATUS, документация и GitHub issue обновлены; нет секретов в поставке.
- [ ] Пояснительная записка `docs/task-results/PM-006.md` содержит изменения, ограничения и доказательства.

## Проверка

OIDC тесты state/nonce/PKCE по выбранному flow, истечение/revocation, горизонтальные и вертикальные проверки прав; реальный вход с настроенным OAuth client.
