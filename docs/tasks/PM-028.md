# PM-028 — Исследование и проектирование встроенных платежей

- **Порядок:** 28; этап 7 — iOS, Windows и коммерческий этап.
- **Приоритет:** P2.
- **Состояние:** deferred.
- **Зависимости:** PM-024, G06.
- **Открытые вводные:** использовать зафиксированные решения; новые блокеры описывать явно.
- **После этапа:** G07 — презентация и минимум 10 отдельных вопросов.

## Цель

Подготовить опциональный коммерческий этап, не менять пилотную заявку на оплату без решения владельца.

## Объём и порядок работы

1. Прочитать регламент, решения, зависимости и связанную GitHub issue.
2. Выбрать регионы/модель продавца/провайдера, описать orders, payment intents, signed callbacks, refunds, reconciliation и ограничения магазинов. Рассмотреть B2B монетизацию отдельно от покупки товара B2C. Реализация платежей — последующие отдельные задачи после решения.
3. Выполнить критерии ниже, обновить документацию и пояснительную записку.

## Ожидаемые результаты

ADR платежей, sandbox сценарии и новый оценённый backlog; без реальных списаний.

## Критерии приёмки

- [ ] Определены участники расчётов, ответственность, состояния и политика повторов. Платёж не объявляется успешным по клиентскому redirect. Владелец принял решение о необходимости этапа.
- [ ] Проверки выполнены и их фактические результаты сохранены.
- [ ] CHANGELOG, STATUS, документация и GitHub issue обновлены; нет секретов в поставке.
- [ ] Пояснительная записка `docs/task-results/PM-028.md` содержит изменения, ограничения и доказательства.

## Проверка

Моделирование duplicate callbacks, timeout/ambiguous status, refund и fraud boundaries; проверка актуальной документации провайдера.

## Фактический результат

Не выполнено. Commit/PR, артефакты и результаты проверки будут добавлены после реализации. Эта issue не закрывается публикацией плана.
