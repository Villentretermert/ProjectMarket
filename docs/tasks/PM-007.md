# PM-007 — Самостоятельная регистрация ботов и индивидуальные ключи

- **Порядок:** 7; этап 2 — Основа, доступ, боты и данные.
- **Приоритет:** P0.
- **Состояние:** in_progress.
- **Зависимости:** PM-006, G01.
- **Открытые вводные:** использовать зафиксированные решения; новые блокеры описывать явно.
- **После этапа:** G02 — презентация и минимум 10 отдельных вопросов.

## Цель

Позволить каждому B2B владельцу безопасно подключать свои HTTP-боты.

## Объём и порядок работы

1. Прочитать регламент, решения, зависимости и связанную GitHub issue.
2. Создать Bot Registry, привязку к владельцу, одноразовый регистрационный credential/flow и отдельный рабочий ключ каждого бота. Хранить проверяемый хеш ключа и открытый prefix, показывать секрет один раз; scopes, ротация, отзыв, квоты, состояние/last_seen. Регистрация бота не даёт административных прав платформы.
3. Выполнить критерии ниже, обновить документацию и пояснительную записку.

## Ожидаемые результаты

Bot management API, миграции, жизненный цикл ключей и инструкция регистрации.

## Критерии приёмки

- [ ] Ключ A не работает для бота B. Отозванный/просроченный ключ отклоняется. Регистрационный токен нельзя использовать повторно. Новые B2B владельцы подключаются без ручного доступа к серверу.
- [ ] Проверки выполнены и их фактические результаты сохранены.
- [ ] CHANGELOG, STATUS, документация и GitHub issue обновлены; нет секретов в поставке.
- [ ] Пояснительная записка `docs/task-results/PM-007.md` содержит изменения, ограничения и доказательства.

## Проверка

Негативные проверки чужого tenant/bot, повторной регистрации, ротации и отзыва; проверка отсутствия ключей в логах и ответах просмотра.

## Фактический результат

Не выполнено. Commit/PR, артефакты и результаты проверки будут добавлены после реализации. Эта issue не закрывается публикацией плана.
