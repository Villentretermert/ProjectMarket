# PM-021 — Production Docker и инструкция облачного запуска

- **Порядок:** 21; этап 6 — Поставка, эксплуатация и приёмка.
- **Приоритет:** P0.
- **Состояние:** planned.
- **Зависимости:** PM-005, PM-012, PM-018, PM-019, PM-020, G05.
- **Открытые вводные:** Q18, Q19.
- **После этапа:** G06 — презентация и минимум 10 отдельных вопросов.

## Цель

Подготовить развёртываемую поставку сайта, API и worker на Linux-хосте.

## Объём и порядок работы

1. Прочитать регламент, решения, зависимости и связанную GitHub issue.
2. Собрать Dockerfile/Compose production: API, worker, PostgreSQL, Web и HTTPS proxy; optional demo bots. Миграции отдельным шагом, health/readiness, persistent volumes, непривилегированные процессы, secrets/config, backup/restore, upgrade/rollback. Выбрать VPS/managed containers после уточнения региона/бюджета. Объектное хранилище не считать средой выполнения Docker.
3. Выполнить критерии ниже, обновить документацию и пояснительную записку.

## Ожидаемые результаты

Production артефакты, .env.example, runbook, оценка ресурсов/стоимости на дату выбора.

## Критерии приёмки

- [ ] Чистый Linux-хост запускает приложение по инструкции; restart не теряет данные; восстановление backup доказано. Сертификаты, OAuth redirects и App Links описаны. Облако не покупается автоматически.
- [ ] Проверки выполнены и их фактические результаты сохранены.
- [ ] CHANGELOG, STATUS, документация и GitHub issue обновлены; нет секретов в поставке.
- [ ] Пояснительная записка `docs/task-results/PM-021.md` содержит изменения, ограничения и доказательства.

## Проверка

Чистое развёртывание, smoke Web/API/bot, migration failure, restart, backup restore и rollback без потери подтверждённых данных.
