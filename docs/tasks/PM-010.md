# PM-010 — Действия клиента, очередь для бота и статусы заявок

- **Порядок:** 10; этап 3 — Backend и интеграция ботов.
- **Приоритет:** P0.
- **Состояние:** in_progress.
- **Зависимости:** PM-007, PM-008, PM-009, G02.
- **Открытые вводные:** использовать зафиксированные решения; новые блокеры описывать явно.
- **После этапа:** G03 — презентация и минимум 10 отдельных вопросов.

## Цель

Реализовать обратную связь: Request purchase (одна единица, без корзины) создаёт событие нужному боту и показывает результат.

## Объём и порядок работы

1. Прочитать регламент, решения, зависимости и связанную GitHub issue.
2. Проверять action_id, bindings, поля и права на сервере. Создавать действие+outbox атомарно; GET pending events с pagination/long poll, отдельные ACK и result endpoint. Повторы и backoff, expiry, дедупликация и terminal state. Заявка не равна оплаченному заказу; тексты UI отражают pending/succeeded/failed.
3. Выполнить критерии ниже, обновить документацию и пояснительную записку.

## Ожидаемые результаты

Action/Event API, worker, state machine и описание доставки at-least-once.

## Критерии приёмки

- [ ] Повтор нажатия с тем же idempotency key не создаёт две заявки. GET/ACK не теряют событие при падении бота. Bot A не видит события Bot B; поддельная цена/чужая карточка отклоняется.
- [ ] Проверки выполнены и их фактические результаты сохранены.
- [ ] CHANGELOG, STATUS, документация и GitHub issue обновлены; нет секретов в поставке.
- [ ] Пояснительная записка `docs/task-results/PM-010.md` содержит изменения, ограничения и доказательства.

## Проверка

Падение до/после ACK, повтор результата, timeout, восстановление pending, чужой пользователь/бот, отключённое действие и отказ бота.
