# PM-008 — Приём сообщений и хранение актуальных данных

- **Порядок:** 8; этап 2 — Основа, доступ, боты и данные.
- **Приоритет:** P0.
- **Состояние:** planned.
- **Зависимости:** PM-004, PM-007, G01.
- **Открытые вводные:** использовать зафиксированные решения; новые блокеры описывать явно.
- **После этапа:** G02 — презентация и минимум 10 отдельных вопросов.

## Цель

Превращать сообщения ботов в надёжно сохранённые данные для чтения клиентом.

## Объём и порядок работы

1. Прочитать регламент, решения, зависимости и связанную GitHub issue.
2. Реализовать POST text/data/event, валидацию схем, ограничение размера/частоты, upsert/delete, дедупликацию по bot_id/message_id, версии и порядок изменений. Хранить текущий снимок и ограниченную историю, серверный timestamp, revision, tenant. Сохранять изменения и outbox в одной транзакции.
3. Выполнить критерии ниже, обновить документацию и пояснительную записку.

## Ожидаемые результаты

Ingestion API, миграции и журнал приёма, актуальные записи и события обновления.

## Критерии приёмки

- [ ] Повтор запроса не дублирует данные; конфликт message_id с иным телом даёт явную ошибку. Позднее сообщение не затирает более новую версию без правила. Сбой не оставляет снимок без события или событие без снимка.
- [ ] Проверки выполнены и их фактические результаты сохранены.
- [ ] CHANGELOG, STATUS, документация и GitHub issue обновлены; нет секретов в поставке.
- [ ] Пояснительная записка `docs/task-results/PM-008.md` содержит изменения, ограничения и доказательства.

## Проверка

Интеграционные проверки concurrent upsert, дубликатов, rollback, перезапуска, размера/лимитов; измерение начальной пропускной способности.

## Фактический результат

Не выполнено. Commit/PR, артефакты и результаты проверки будут добавлены после реализации. Эта issue не закрывается публикацией плана.
