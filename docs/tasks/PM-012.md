# PM-012 — Проверка полного backend-цикла и восстановление после сбоев

- **Порядок:** 12; этап 3 — Backend и интеграция ботов.
- **Приоритет:** P0.
- **Состояние:** planned.
- **Зависимости:** PM-009, PM-010, PM-011, G02.
- **Открытые вводные:** использовать зафиксированные решения; новые блокеры описывать явно.
- **После этапа:** G03 — презентация и минимум 10 отдельных вопросов.

## Цель

Подтвердить работоспособность платформенного ядра до разработки полного UI.

## Объём и порядок работы

1. Прочитать регламент, решения, зависимости и связанную GitHub issue.
2. Собрать сценарий Google user/B2B → бот → канал → сообщение → read → действие → GET → ACK/result. Проверить закрытый канал, отзыв ключа, конкурентные обновления и восстановление worker. Использовать API harness, не выдавать его за готовый клиент. Зафиксировать baseline latency и throughput.
3. Выполнить критерии ниже, обновить документацию и пояснительную записку.

## Ожидаемые результаты

Интеграционный стенд, воспроизводимые сценарии и отчёт PM-012.

## Критерии приёмки

- [ ] Два независимых бота обслуживают два канала; данные и действия не смешиваются. После рестарта принятые сообщения и незавершённые действия восстанавливаются. Нет потерь между фиксацией БД и обработкой outbox.
- [ ] Проверки выполнены и их фактические результаты сохранены.
- [ ] CHANGELOG, STATUS, документация и GitHub issue обновлены; нет секретов в поставке.
- [ ] Пояснительная записка `docs/task-results/PM-012.md` содержит изменения, ограничения и доказательства.

## Проверка

End-to-end API проверки с реальной БД/worker и fault injection; проверка 1 000 сообщений/мин как проектного сценария и объяснение результатов.
