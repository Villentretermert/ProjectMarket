# PM-009 — Каналы, публикация и чтение news/product/chart блоков

- **Порядок:** 9; этап 3 — Backend и интеграция ботов.
- **Приоритет:** P0.
- **Состояние:** planned.
- **Зависимости:** PM-004, PM-008, G02.
- **Открытые вводные:** использовать зафиксированные решения; новые блокеры описывать явно.
- **После этапа:** G03 — презентация и минимум 10 отдельных вопросов.

## Цель

Отдавать клиентам быстрый и разрешённый интерфейс канала из сохранённых данных.

## Объём и порядок работы

1. Прочитать регламент, решения, зависимости и связанную GitHub issue.
2. Реализовать Channel, draft/published PageVersion, Block/Binding, URL/slug, public/private grants, preview/publish/rollback. Read API отдаёт schema+data revision, pagination, ETag/условное чтение и свежесть; удаление источника приводит к понятному состоянию. У chart есть типизированный набор числовых данных; не строить графики из произвольного текста.
3. Выполнить критерии ниже, обновить документацию и пояснительную записку.

## Ожидаемые результаты

API страниц и блоков, версии шаблонов и документация публикации.

## Критерии приёмки

- [ ] Публичные ответы не включают закрытые поля; закрытая страница не доступна по одному знанию URL. Старый опубликованный шаблон остаётся воспроизводимым; кеш учитывает пользователя и права.
- [ ] Проверки выполнены и их фактические результаты сохранены.
- [ ] CHANGELOG, STATUS, документация и GitHub issue обновлены; нет секретов в поставке.
- [ ] Пояснительная записка `docs/task-results/PM-009.md` содержит изменения, ограничения и доказательства.

## Проверка

Проверка публикации/отката, запрета доступа, смешанного кеша, пагинации, пустого/удалённого источника и совместимости schema/data.

Не выполнено. Commit/PR, артефакты и результаты проверки будут добавлены после реализации. Эта issue не закрывается публикацией плана.
