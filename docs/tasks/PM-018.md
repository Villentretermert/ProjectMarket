# PM-018 — Быстрые локальные обновления и выбранные события

- **Порядок:** 18; этап 5 — Обмен, обновления, Android и виджет.
- **Приоритет:** P1.
- **Состояние:** done.
- **Зависимости:** PM-008, PM-010, PM-013, PM-016, PM-017, G04.
- **Открытые вводные:** использовать зафиксированные решения; новые блокеры описывать явно.
- **После этапа:** G05 — презентация и минимум 10 отдельных вопросов.

## Цель

Обновлять открытый клиент за секунды и показывать выбранные события без облачного провайдера.

## Объём и порядок работы

1. Прочитать регламент, решения, зависимости и связанную GitHub issue.
2. Добавить SSE/WebSocket или обоснованный polling, reconnect с cursor и snapshot resync, подписки и пользовательские preferences. Реализовать события внутри открытого клиента, дедупликацию, минимальный payload и отзыв доступа. Оставить границу будущего push-provider без зависимости от Firebase. Background push/Web Push отложены по последнему ответу владельца.
3. Выполнить критерии ниже, обновить документацию и пояснительную записку.

## Ожидаемые результаты

Локальный live update клиент/сервер, выбранные события, Android delivery contract и метрики. Фоновая доставка не заявляется.

## Критерии приёмки

- [x] Открытый Web-клиент выполняет согласованный SLO PM-001; reconnect не теряет обновления. Уведомления приходят только подписанным и имеющим доступ пользователям. Отказ в разрешении не ломает приложение.
- [x] Проверки выполнены и их фактические результаты сохранены.
- [x] CHANGELOG, STATUS, документация и GitHub issue обновлены; нет секретов в поставке.
- [x] Пояснительная записка `docs/task-results/PM-018.md` содержит изменения, ограничения и доказательства.

## Проверка

Reconnect/перестановка событий, revoked access, отключение компьютера и восстановление локальной связи. Background push не проверяется и не включается в приёмку этого локального этапа.
