# PM-018 — Быстрые обновления и push по выбранным событиям

- **Порядок:** 18; этап 5 — Обмен, обновления, Android и виджет.
- **Приоритет:** P1.
- **Состояние:** planned.
- **Зависимости:** PM-008, PM-010, PM-013, PM-016, PM-017, G04.
- **Открытые вводные:** использовать зафиксированные решения; новые блокеры описывать явно.
- **После этапа:** G05 — презентация и минимум 10 отдельных вопросов.

## Цель

Обновлять открытый клиент за секунды и подготовить адресную доставку push.

## Объём и порядок работы

1. Прочитать регламент, решения, зависимости и связанную GitHub issue.
2. Добавить SSE/WebSocket или обоснованный polling, reconnect с cursor и snapshot resync, подписки и пользовательские preferences. Реализовать серверную доставку Web Push и Android push endpoint/provider interface, хранение токенов устройства, дедупликацию, минимальный payload и отзыв. В Android фактическое получение проверяется в PM-019.
3. Выполнить критерии ниже, обновить документацию и пояснительную записку.

## Ожидаемые результаты

Live update клиент/сервер, Web Push, Android delivery contract и метрики.

## Критерии приёмки

- [ ] Открытый Web-клиент выполняет согласованный SLO PM-001; reconnect не теряет обновления. Уведомления приходят только подписанным и имеющим доступ пользователям. Отказ в разрешении не ломает приложение.
- [ ] Проверки выполнены и их фактические результаты сохранены.
- [ ] CHANGELOG, STATUS, документация и GitHub issue обновлены; нет секретов в поставке.
- [ ] Пояснительная записка `docs/task-results/PM-018.md` содержит изменения, ограничения и доказательства.

## Проверка

Reconnect/перестановка событий, revoked access, stale device tokens, denied permission и Web Push с тестовым провайдером/браузером.

## Фактический результат

Не выполнено. Commit/PR, артефакты и результаты проверки будут добавлены после реализации. Эта issue не закрывается публикацией плана.
